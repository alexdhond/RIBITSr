# AGENTS.md

## Project Overview

**ribits** is an R package for programmatic access to the USACE RIBITS (Regulatory In-lieu Fee and Bank Information Tracking System) API. It enables researchers and practitioners to retrieve data on wetland mitigation banks, ILF (In-Lieu Fee) programs, and umbrella instruments across the United States.

### Target Users
- Environmental researchers studying biodiversity offset markets
- Ecology PhD students analyzing compensatory mitigation
- Environmental consultants needing bank/credit data
- Policy analysts studying wetland regulation

## API Reference

### Base URL
```
https://ribits.ops.usace.army.mil/ords/RI/public/
```

### Working Endpoints

| Endpoint | Description | Key Parameters |
|----------|-------------|----------------|
| `bank_site_list/` | List banks with filters | kind_of_bank, district, state, noaaregion, fieldoffice |
| `bank_site_data/` | Bank details | bank_id (required), show_service_area, show_footprint, show_contacts, show_ledger |
| `ilf_program_list/` | List ILF programs | Similar filters |
| `ilf_program_data/` | ILF program details | program_id (required), similar show_* params |
| `umbrella_instrument_list/` | List umbrella instruments | Similar filters |
| `umbrella_instrument_data/` | Umbrella details | umbrella_id (required) |
| `wqt_project_list/` | List WQT projects | (needs exploration) |

### Query Format
```
GET {base_url}{endpoint}/?q={"param":"value","param2":"value2"}
```

### Rate Limiting
- Use 0.5-1 second delays between requests
- Include `webconsumer_email` parameter for tracking
- Batch large downloads with progress reporting

## Coding Standards

### Function Naming
- Public functions: `rb_*()` prefix (e.g., `rb_list_banks()`, `rb_get_bank()`)
- Internal functions: `.rb_*()` prefix (e.g., `.rb_parse_response()`)
- Extractors: `rb_extract_*()` (e.g., `rb_extract_ledger()`)
- Parsers: `rb_read_*()` for CSV files (e.g., `rb_read_credit_tracking()`)

### Style Guide
- Use tidyverse style: snake_case, pipes (`|>` or `%>%`)
- Max line length: 80 characters
- Use explicit `return()` for clarity in complex functions
- Prefer `NULL` over missing for optional arguments

### Documentation (roxygen2)
```r
#' Get bank details from RIBITS
#'
#' Retrieves detailed information for a specific mitigation bank,
#' optionally including service areas, footprint geometry, contacts,
#' and transaction ledger.
#'
#' @param bank_id Integer. The unique RIBITS bank identifier.
#' @param service_area Logical. Include service area geometries? Default TRUE.
#' @param footprint Logical. Include bank footprint geometry? Default TRUE.
#' @param contacts Logical. Include contact information? Default TRUE.
#' @param ledger Logical. Include transaction ledger? Default TRUE.
#'
#' @return A list containing bank attributes and requested nested data.
#'   Use `rb_extract_*()` functions to extract specific components.
#'
#' @export
#' @examples
#' \dontrun{
#' # Get bank with all details
#' bank <- rb_get_bank(17)
#' 
#' # Get bank without spatial data
#' bank <- rb_get_bank(17, service_area = FALSE, footprint = FALSE)
#' 
#' # Extract ledger as tibble
#' ledger <- rb_extract_ledger(bank)
#' }
```

### Error Handling
```r
# Use rlang for errors
if (is.null(bank_id)) {
rlang::abort(
    "bank_id is required",
    class = "ribits_error_missing_param"
  )
}

# Use cli for user messages
cli::cli_alert_info("Fetching {length(bank_ids)} banks...")
cli::cli_alert_success("Retrieved {nrow(result)} banks")
cli::cli_alert_warning("Rate limit reached, waiting...")
```

### Return Types
- List endpoints → tibble
- Detail endpoints → list (with nested components)
- Spatial extractors → sf object
- Data extractors → tibble

## Data Not in API (Requires Manual Download)

These data require manual CSV download from RIBITS website:
1. **Credit Classification by Jurisdiction** - detailed credit type breakdowns
2. **Potential Credits by Mitigation Type** - establishment, enhancement, etc.
3. **Detailed Transaction Data** - permittee, permit number, project name
4. **Service Area Comments** - text descriptions

The `rb_read_*()` functions parse these manually downloaded CSVs.
